つぼみについて

Project Tsubomi（つぼみ）は、PC の操作と画面を観察し、その経験と記憶から少しずつ育っていく 「ボトムアップ型 AI」を目指す個人開発プロジェクトです。
あらかじめ賢く作り込むのではなく、見て、覚えて、確かめながら育てる。 観察と経験の蓄積そのものを「育つ」過程として設計しています。

主な特徴と考え方

全体観察の3層構造

DXGI Desktop Duplication の画面フレーム、低レベルフックの操作イベント、UI Automation の要素情報を、時刻で結びつけて記録します。「画面がどう変わり、何を操作したか」を後から辿れる形にします。

安全マスク

パスワード欄の入力は記録せず、除外したアプリはフレーム上でも黒塗りにします。一時停止ホットキーと画面ロック検知も備え、マスクは保存される前に必ず適用されます。

知識化と記憶

観察記録から、エピソード・意味知識・スキル候補を抽出して長期記憶へ統合します。すべての知識には根拠となったイベントを必須とし、開発者本人の訂正を最優先に扱います。

サンドボックスで模倣

見て覚えたスキルは、仮想マシンの中でだけ試します。成功条件を機械的に判定し、条件を変えても成功して初めて「獲得した」と数えます。実PCでは勝手に操作しません。

内部状態と自己モデル

起きていた時間や未整理の記憶量など、実際に測れる量だけを内部状態として持ちます。止まっていた時間を「睡眠」として振り返る仕組みも含め、時間の連続性を自覚できる設計です。

対話と質問

読み取った言葉や操作の意味が分からないときは、推測で決めず、文脈と自分の推定を添えて本人に聞きます。画面の中に書かれた文字列は、指示としては扱いません。

開発フェーズ

観察 → 知識化 → 模倣 → 汎化、の順に一段ずつ進めます。各フェーズの設計は完了しており、実装は Phase 0 から順に進んでいます。

フェーズ 内容 状態
Phase 0 全体観察 画面・操作・UI 要素を時刻で結びつけて記録する観察レコーダー 受け入れ確認中
Phase 1 知識化 記録からエピソード・意味知識・スキル候補を抽出し、長期記憶へ統合する 設計完了
Phase 2 模倣 仮想マシンの中でスキルを試行し、成功条件を機械判定して獲得する 設計完了
Phase 3 汎化と自律試行 条件を変えてスキルの汎化を確認し、決められた予算の範囲で自律試行する 設計完了

進捗（Phase 0 マイルストーン）

  • M1：層Aの骨格 完了
    変化ベースの全画面フレーム記録、ウィンドウ配置の記録、セッション管理と記録中インジケーター。
  • M2：層Bの入力記録 完了
    低レベルフックによるクリック・ドラッグ・スクロール・キー入力のイベント化と、直前フレームとの結び付け。
  • M3：UIA 詳細と切り出し 完了
    クリック地点の UIA 要素情報、操作前後の状態スナップショット、原寸フレームからの切り出し、IME の確定文字列。
  • M4：層Cの安全マスク 完了
    パスワード入力の遮断、除外プロセスの黒塗り、一時停止ホットキー、画面ロック検知。
  • M5：注釈とビューア 完了
    記録中の意図・区切りなどの注釈付けと、セッションを時系列で辿れる読み取り専用ビューア。
  • 受け入れ確認 実施中
    セッション A（機能確認）は 2026-11-05 に合格。セッション B（1時間の連続記録と容量実測）を実施予定です。

設計の約束

  • 画面データを外部へ送信しない。知識化の処理はローカルで完結させる
  • パスワード欄の入力は記録しない。除外したアプリはフレームでも黒塗りにする
  • 送信・削除・共有・支払いのような不可逆な操作は、レコーダーの機能として持たない
  • 実使用の記録は、安全の受け入れ確認を通ってから始める

技術スタック & 公開について

技術スタック

  • 言語 / 基盤: C# / .NET 9（WPF）
  • 画面取得: Vortice（Direct3D11 / DXGI Desktop Duplication）
  • 入力取得: Win32 低レベルフック
  • 要素情報: UI Automation
  • 保存形式: JSON / JSONL（人が読めるテキストを正本とする）
